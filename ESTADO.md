### Cómo se migró la base de datos

`scripts/mysql-a-postgres.mjs` convierte `database/schema.mysql.sql` a
`database/schema.postgres.sql`. Se hizo con un script y no a mano para que la
conversión fuera reproducible y revisable:

| Transformación | Cuántas |
|---|---|
| `AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY` | 52 |
| `ENUM(...)` → `CREATE TYPE ... AS ENUM` | 39 |
| `TINYINT(1)` → `BOOLEAN` (y `DEFAULT 1/0` → `TRUE/FALSE`) | 37 |
| `DATETIME` / `TIMESTAMP` → `TIMESTAMPTZ` | 48 |
| `ON UPDATE CURRENT_TIMESTAMP` → trigger `set_actualizado_en()` | 8 |
| `FULLTEXT KEY` → índice GIN sobre `to_tsvector('spanish', ...)` | 1 |
| `JSON` → `JSONB`, `MEDIUMTEXT` → `TEXT`, `CHAR(n)` → `VARCHAR(n)` | 20 |
| Claves ajenas movidas a `ALTER TABLE` al final | 91 |

Lo último resuelve un problema real: MySQL cargaba las tablas en cualquier orden
porque apagaba `FOREIGN_KEY_CHECKS`, y en PostgreSQL eso no existe.

Las 8 plantillas de reporte llevan SQL guardado como texto, así que se
reescribieron a mano en `scripts/plantillas-reporte-postgres.mjs`
(`DATE()` → `::date`, `HOUR()` → `EXTRACT`, `CONCAT(a," ",b)` → `a || ' ' || b`,
`SUM(<booleano>)` → `COUNT(*) FILTER (WHERE ...)`).

### Backend

Núcleo en `apps/api/src/nucleo/`:

| Pieza | Responsabilidad |
|---|---|
| `prisma/` | Cliente de base, con aviso de no usar `db push` |
| `autenticacion/tokens.service.ts` | JWT HS256 + refresh opaco rotatorio |
| `autenticacion/permisos.service.ts` | RBAC desde la base, con caché por rol |
| `autenticacion/contexto.service.ts` | Resuelve el usuario desde el token |
| `autenticacion/*.guard.ts` | Sesión y permisos, globales y cerrados por defecto |
| `validacion/` | Pipe de Zod contra los esquemas de `@aurora/contratos` |
| `respuesta/` | Forma única `{ ok, mensaje?, datos, meta? }` |
| `errores/` | Traducción de cualquier error a la forma única |
| `bitacora/` | Auditoría que enmascara contraseñas y tokens, y nunca corta la operación |

Módulos implementados: **salud** y **auth** (registro, login, refresh, logout,
perfil, cambio de contraseña).

Contrato REST autodocumentado en `/api/docs`.

**Pruebas: `node scripts/probar-api.mjs` — 43 comprobaciones, 43 en verde**,
partiendo de una base recién creada. Cubren:

```
Salud              servicio y base viva, sin exigir sesión
Login              correcto / contraseña mala / correo inexistente / datos inválidos
                   el mensaje no distingue correo inexistente de contraseña mala
Perfil             con token / sin token / firma adulterada / alg=none / método no declarado
Refresh            rotación, el token usado deja de servir, logout lo revoca
Registro           alta, correo repetido, mayorista sin NIT, contraseña corta
Contraseña         actual incorrecta, cambio correcto, cierra las demás sesiones
Bloqueo            5 intentos fallidos bloquean la cuenta 15 minutos
Límite de tasa     corta pasadas 10 peticiones y es por IP
Bitácora           login, login_fallido, crear, logout, actualizar — con IP y agente
```

### Seguridad

- `npm audit`: **0 vulnerabilidades**. Hizo falta forzar `multer` a 2.3.0 —
  `@nestjs/platform-express` arrastra la 2.2.0, que tiene cuatro avisos de
  denegación de servicio por multipart, y es justo la que recibirá las imágenes
  de producto.
- El JWT se verifica con `algorithms: ['HS256']`, lo que bloquea el ataque de
  `alg=none` (hay una prueba que lo comprueba).
- Del refresh se guarda solo el SHA-256: leer la tabla `sesion` no sirve para
  entrar.
- `trust proxy` está puesto para que detrás del proxy de Azure el limitador vea
  la IP real del cliente y no la del balanceador.
